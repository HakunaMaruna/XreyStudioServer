# Мастер создания ноды

Мастер (`/wizard` в панели, `POST /api/wizard/nodes`) заменяет ручное добавление ноды
и запуск `add-node.sh` вручную.

## Шаги

1. **Доступ по SSH**: IP/домен, пользователь (`root` или sudo-пользователь), порт,
   отпечаток host-ключа `SHA256:...` и один из трёх режимов:
   - пароль;
   - пароль + приватный ключ (с паролем ключа);
   - только ключ.
2. **Домен и локация**: имя ноды, страна из списка ISO 3166-1 alpha-2 с флагом
   (`RU 🇷🇺`, `US 🇺🇸`, … — 249 стран), IPv4/IPv6, необязательный собственный домен.
3. **Результат**: выданный FQDN, первое подключение VLESS TLS, кнопки
   «Применить конфиг» и «Повторить выпуск сертификата».

## Что делает мастер

- Запрашивает у CONTROL уникальный домен `<12 hex>.node.h2onetwork.pro`
  (A/AAAA, TTL 60) либо использует локальный CONTROL этой же панели.
- Проверяет CNAME для пользовательского домена (см. `docs/control-dns.md`).
- Устанавливает агента через SSH: клонирует репозиторий, если Docker отсутствует —
  ставит его, пишет `.env` с `NODE_ID`/`AGENT_TOKEN`, запускает `install.sh --mode node`.
- Создаёт inbound `vless` + `tls` с SNI = выданному домену, ревизию конфига
  и выпускает сертификат DNS-01 (на оба имени, если указан свой домен).
- При ошибке установки домен автоматически освобождается.

## Безопасность

- SSH-пароль, ключ и пароль ключа сохраняются только в зашифрованном виде
  (AES-256-GCM, ключ `PANEL_MASTER_KEY`); API возвращает лишь факты наличия секретов.
- Отпечаток host-ключа обязателен — защищает от MITM при первой установке.
- В логах маскируются все секреты; `agentToken` хранится в БД только хешем и не возвращается повторно.
- Удалить сохранённые креды: `DELETE /api/wizard/credentials/:nodeId`.

## Ограничения

- `SSH_PROVISION_ENABLED=true` должно быть включено на TENANT-панели.
- Удалённый агент поднимается только через `docker-compose.node.yml` (без `depends_on: backend`), чтобы на ноде не собиралась вся панель.
- Вывод удалённых команд транслируется в окно установки; таймаут команды — `NODE_PROVISION_COMMAND_TIMEOUT_MS` (по умолчанию 600 с).
- Первый inbound использует порт `WIZARD_INBOUND_PORT` (по умолчанию 443).
- По умолчанию используется автоматический поддомен CONTROL. Свой домен доступен переключателем; без чекбокса сертификата TLS остаётся на автоматическом домене.
- Если DNS пользовательского домена ещё не настроен, сертификат выпускается только
  для выданного домена; повторите через `/api/wizard/certificates/retry`.
- VLESS + TLS выбран вместо Reality: сертификат required и для выданного, и для
  пользовательского домена.
