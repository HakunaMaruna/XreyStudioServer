# v2.6.1 QA gaps: Settings API, regression #83, full CI

Date: 2026-11-23 UTC. Scope: issue #85. Agent 2 (CI/infrastructure/QA).
Base: `origin/main` `0952d05` (v2.6.1), merged into the QA branch so PR #82 now covers
#79, #77 and #85. Product code (`backend/src`, `frontend/src`), versions and releases untouched.

## Tests added

- `backend/test/settings.e2e-pg-spec.ts` (2 tests):
  - anonymous `GET`/`PATCH /api/settings` → 401;
  - ADMIN `GET` returns defaults (`language`, `theme`, `alertsEnabled`, `metricsEnabled`,
    `rateLimit`, `sessionMinutes`); `PATCH` persists changes and clamps `rateLimit` to
    `[1, 10000]` and `sessionMinutes` to `[1, 1440]`; a second `GET` confirms persistence.
  - OPERATOR (tenant A) and USER (tenant B) get 403 for both `GET` and `PATCH`, and their
    attempts do not change the stored settings — Settings is global but ADMIN-only.
  - `SETTINGS_FILE` is pointed at a temporary directory in `backend/test/setup-env-pg.js`,
    so e2e writes never touch the repository `backups/` folder.
- `backend/test/ux-v25.e2e-pg-spec.ts` (new 4th test): regression #83 — a user bound to an
  inbound only through `clients[]` now gets a `trojan://` subscription link containing the
  `subscriptionToken` from both `/api/subscriptions/:token/json` and `/raw`. The fix in
  `SubscriptionsService.loadUser()` (`inboundClients` are merged with direct `inbounds`) is
  covered; on the pre-fix v2.4.x code this test fails.
- `bench/scenarios/smoke.js`: `PROTECTED` now includes `/api/settings` and `/api/routing`
  (the correct v2.5/v2.6 routing path; `/api/routing/profiles` is not a route). Anonymous
  checks expect 401; with `LIVE_ADMIN_EMAIL`/`LIVE_ADMIN_PASSWORD` secrets the same endpoints
  are read with a bearer token and at least one node must be `ONLINE`.
