# UX/a11y-ревью v2.8.0 (issue #93, продолжение #80/#67)

Read-only ревью актуального UI v2.8.0 (main `557f182`). Метод: дерево доступности
(accessibility tree), computed-стили и контраст через headless-браузер, чтение
исходников frontend без изменений. Проверены: `/squads`, `/config-profiles`,
`/routing`, карточка пользователя («Ключ подключения»), `/users`, `/settings`,
`/login`, мобильный viewport 390px.

Итог: интерфейс визуально цельный, клавиатурный доступ к элементам есть, Escape
закрывает модалки, у кнопок-иконок есть aria-label. Основные системные проблемы:
модалки не являются диалогами для AT, подписи полей не связаны с input,
слабый контраст вспомогательного текста и мелкий шрифт, устаревшая версия в UI.

## 1. Критично для скринридеров (a11y)

### A1. Модалки не размечены как диалоги
Ни одна модалка («Создать» в squads/routing/config-profiles, «Ключ подключения»)
не имеет `role="dialog"`, `aria-modal="true"` или `aria-labelledby` на заголовок
(проверено в DOM: `[role=dialog]` — 0 элементов). Скринридер не объявляет режим
диалога; фоновый контент остаётся доступным для Tab — **фокус-ловушки нет**.
Escape при этом работает (плюс).
WCAG 2.1: 4.1.2 Name, Role, Value.

### A2. Фокус при открытии модалки не переносится внутрь
После открытия диалога `document.activeElement` остаётся на кнопке «Создать» под
оверлеем. Клавиатурному пользователю нужно несколько Tab, чтобы попасть в форму.
WCAG 2.4.3 Focus Order.

### A3. Label не связаны с полями
Во всех формах (`squads`, `routing`, `config-profiles`, фильтры `/users`)
`<label>` без `for`, у `<input>/<textarea>/<select>` нет `id` и `aria-label`
(проверено: `htmlFor: null`, `id: ""` для всех 5 полей модалки squads).
Связь только визуальная через вложенность — AT в ряде режимов (iOS/VoiceOver,
braille-режимы) её теряет. WCAG 1.3.1, 3.3.2, 4.1.2.

### A4. Переключатель «Включено» — button без состояния
Кнопка-тумблер не имеет `role="switch"`/`aria-pressed`/`aria-checked`
(проверено: все null). Состояние on/off визуально есть, для AT — нет.
WCAG 4.1.2.

### A5. `<title>` пуст на всех страницах
`document.title === ""`. Вкладки/история навигации не различимы.
WCAG 2.4.2 Page Titled. Также нет skip-ссылки к `<main>` (WCAG 2.4.1).

### A6. Поиски без доступного имени
Поле сайдбара «Поиск страниц…» и поиск таблиц опознаются только по placeholder;
`aria-label`/`label` отсутствуют. Подсказка-клавиша «/» визуально есть,
объявления о горяче клавише — нет. WCAG 3.3.2, 4.1.2.

### A7. Поле пароля: «плавающее» имя
У input пароля доступное имя собирается как «ПАРОЛЬ Toggle password» —
внешняя кнопка показа пароля попадает в computed name поля.
WCAG 2.5.3 Label in Name.

## 2. Контраст и читаемость

### C1. `text-subtle` не проходит WCAG AA
`rgb(100,114,138)` на фоне `rgb(8,11,18)` = **4.04:1** — ниже 4.5:1 для мелкого
текста. Используется для критичной мета-информации: «ID 516afffe» (10px),
подсказки полей, футер логина. 10px шрифт сам по себе ниже разумного минимума
для dense-UI. WCAG 1.4.3.

### C2. Капслок-подписи полей мелким шрифтом
Лейблы «НАЗВАНИЕ», «ЛИМИТ ТРАФИКА GB» — ~10–11px; единица измерения «GB»
вынесена из подписи под поле и не входит в доступное имя
(spinbutton называется «ЛИМИТ ТРАФИКА GB», но визуально «GB» отдельно — ок для
AT, плохо для сканирования глазами).

## 3. Мобильная версия (390px)

### M1. Таблицы — горизонтальный скролл без индикации
На `/users` колонки «Статус/Лимит/Действия» обрезаны; горизонтальный скролл
таблицы есть, но визуально не подсвечен (нет тени/индикатора), sticky-колонки
нет. Пользователь может не догадаться, что справа есть действия.
WCAG 1.4.10 Reflow (частично: контент доступен, но discovery страдает).

### M2. Карточка пользователя на мобильном — ок
Модалка «Ключ подключения» адаптируется хорошо: всё в одну колонку, кнопки
достаточного размера.

## 4. Понятность workflow (UX)

### U1. Путь «создать пользователя → получить ключ → привязать к подключению»
Прослеживается, но с разрывами:
- После создания пользователя модалка закрывается без явного продолжения —
  чтобы получить ключ, нужно догадаться нажать иконку-«ключ» в колонке
  «ДЕЙСТВИЯ», которая не подписана текстом (доступное имя «Ключ подключения»
  есть — для AT ок, для новичка иконка неоднозначна: похоже на «API-ключ»).
- Кнопки экспорта **JSON / CLASH / SINGBOX / BASE64** — капслок-аббревиатуры без
  пояснения, что это форматы клиентских конфигов; порядок не подписан.
- «Привязать к подключению»: селект «Выберите подключение» + отдельная кнопка
  «+ Привязать к подключению» — дублирование действия; состояние «что выбрано и
  применено» после привязки не показывается.
- Ссылка подписки и все ссылки экспорта строятся из `PANEL_URL`
  (`users.service.ts:64-73`). **Если `PANEL_URL` не задан, пользователь копирует
  относительный путь `/sub/<token>`** — в клиенте VPN это нерабочая ссылка, а
  визуально она выглядит как готовая. Нужен явный fallback на origin запроса
  либо предупреждение в UI. Это главный finding workflow.

### U2. Группы пользователей и профили конфигурации — почти двойники
`squads` и `config-profiles` выглядят одинаково (та же таблица, те же поля
«Название/Комментарий/Включено»), различия по смыслу не объяснены ни в
подзаголовках, ни в пустых состояниях. Пустое состояние — англоязычное
«Try adjusting your filters or create a new record.» в русском UI (i18n-протечка).

### U3. «Маршрутизация»: PAYLOAD (JSON) с значением `[]`
Форма создаёт профиль с сырым JSON без схемы/подсказки формата, без валидации
до отправки и без сообщений об ошибке в модалке (role=alert в форме отсутствует).
Опытному админу ок, новичку — source of errors.

### U4. Настройки: версия сборки устарела
Страница «Настройки» показывает **Версия: 2.6.1** при фактических пакетах
2.8.0: константа `frontend/src/lib/version.ts APP_VERSION` обновляется вручную
и отстала на два релиза (в v2.7/v2.8 её пропустили). Диагностика окружения,
которая врёт, хуже, чем её отсутствие.

### U5. CORS `*` в поле «CORS»
Значение по умолчанию `*` показано как обычное редактируемое поле без
предупреждения о безопасности.

## 5. Позитив

- Escape закрывает все проверенные модалки; кнопка Close имеет aria-label.
- Иконки-кнопки в таблице и карточке имеют доступные имена (0 безымянных).
- Навигационные landmark'ы на месте: banner/nav/aside/main.
- Язык документа корректный (`lang="ru"`), переключение RU/EN доступно.
- Фокус-стили присутствуют (есть `:focus-visible`-правила, outline не подавлен).
- Модалки на мобильном не ломаются.

## Рекомендации (по приоритету)

1. **P1:** модалки — `role="dialog" aria-modal="true" aria-labelledby`,
   перенос фокуса внутрь при открытии, возврат фокуса на триггер, ловушка Tab.
2. **P1:** подписки/экспорт при пустом `PANEL_URL` — абсолютный URL из запроса
   или явное предупреждение в карточке пользователя (U1).
3. **P1:** label↔control: `id`/`htmlFor` (или `aria-label`) во всех формах.
4. **P2:** `text-subtle` → контраст ≥ 4.5:1 (например `rgb(125,140,166)`),
   мета-текст «ID …» ≥ 12px (C1).
5. **P2:** тумблеры — `role="switch"` + `aria-checked` (A4).
6. **P2:** `document.title` по страницам + skip-link (A5).
7. **P2:** синхронизация `APP_VERSION` с package.json на релизе (CI-проверка) (U4).
8. **P3:** мобильные таблицы — индикатор горизонтального скролла (M1);
   русификация пустых состояний DataTable (U2); пояснения к JSON-payload (U3);
   различие формулировок squads vs config-profiles (U2).

Найдено в ходе ревью; продуктовый код не изменялся.
