# QA: v2.7.0 user config profiles

Scope: issue #90, agent 2 zone only (`.github/workflows`, `backend/test`, `docs/reports`, `bench`).
Product code, versions and releases untouched. Feature under test: PR #89 (`0a5f1b7`).

## Coverage

`backend/test/config-profiles.e2e-pg-spec.ts` (4 PostgreSQL e2e tests):

1. **CRUD and persistence** — empty list, `POST` with a `routingRules`/`dnsServers`/`outbounds`
   payload, list with `_count.users`, `GET :id`, `PATCH` (rename, disable, replace payload),
   re-read after persistence, `DELETE` and empty list afterwards.
2. **RBAC** — anonymous `GET`/`POST` → 401; `USER` `GET`/`POST`/`PATCH`/`DELETE` → 403 with no
   mutation; `OPERATOR` can list/create/update/delete; admin access unchanged.
3. **Profile → node config** — `PATCH /users/:id` with `configProfileId` persists the relation;
   after `POST /nodes/:id/apply` the agent config contains the profile's routing rule, DNS server
   and outbound alongside the user's inbound client. The list reports `_count.users: 1`.
4. **Disabled/detached/tenant scope** — a disabled profile is ignored in a freshly applied config;
   a node in another organization never receives the payload; `PATCH /users/:id` with
   `configProfileId: null` detaches the user (matching the frontend select) and the payload
   disappears after re-apply.

`bench/scenarios/smoke.js`: `/api/config-profiles` added to `PROTECTED`, so the live smoke checks
anonymous rejection on PRs, pushes to main, nightly and manual runs; authenticated reads are
covered when `LIVE_ADMIN_EMAIL`/`LIVE_ADMIN_PASSWORD` secrets are set.

## Notes / follow-ups (product code outside this zone)

- `GET /api/config-profiles/:id` for a missing id returns HTTP 200 with an empty body rather than
  404 (the service returns `findUnique()` directly). The e2e test asserts the current behaviour;
  a proper 404 would be a product change.
- `PATCH /users/:id` with `configProfileId: null` works: `class-validator`'s `@IsOptional()` treats
  `null` as absent, so the service takes the `disconnect` branch. Verified by test 4.
- Authenticated live smoke checks (including node ONLINE) remain skipped: no live admin credentials
  are available in this environment.
