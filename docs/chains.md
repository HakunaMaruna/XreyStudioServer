# VPN-цепочки (entry → exit)

Реализация следует модели Mistgate **relay**: нода-вход пересылает зашифрованный TCP-трафик
на выход как есть, не имея ключей выхода. Клиент видит дубликат сервера с адресом входа.

## Сущности

- `ProxyChain` — название, статус, режим маршрутизации (`all`/`rules`), организация.
- `ProxyChainHop` — вход (порт ретрансляции) и один или несколько выходов (порт, приоритет,
  VLESS Reality-ключи, UUID).
- `ChainBinding` — привязка цепочки к пользователю или группе (squad). Персональная
  привязка имеет приоритет над групповой.

## API

- `GET /api/chains`, `POST /api/chains`, `PATCH /api/chains/:id`, `DELETE /api/chains/:id`
- `POST /api/chains/:id/apply` — применить конфигурацию и ретрансляции
- `GET /api/chains/:id/status`
- `POST /api/chains/:id/bind`, `DELETE /api/chains/:id/bind/:bindingId`
- `GET/DELETE /api/chains/binding/user/:userId`

## Правила

- Вход и выход не могут быть одной нодой; проверяются циклы по графу цепочек.
- Ноды должны быть онлайн; порты выбираются автоматически или явно и не пересекаются.
- При откате apply возвращаются предыдущие ретрансляции.
- Подписка получает только entry-адрес; выходы скрыты от клиента.
- Резервные выходы передаются агенту входа как `targets` с приоритетами: при недоступности
  основного TCP-соединение переключается на резервный без участия клиента. В подписке client
  видит только один сервер входа.

## Агент

`POST /relays` с телом `{relays:[{id,listenPort,targetHost,targetPort,enabled}]}`.
Конфиг сохраняется в `/etc/xss-agent/relays.json` и восстанавливается после перезапуска.

Обратная миграция: `backend/prisma/chain-down.sql`.

## Живая привязка групп к подключениям

`InboundSquad` хранит связь подключения (`Inbound`) и группы пользователей (`Squad`).
Клиенты, добавленные через такую связь, помечаются `InboundClient.sourceSquadId`,
поэтому ручные клиенты никогда не удаляются при синхронизации.

- `GET /api/inbounds/:id/squads`, `POST /api/inbounds/:id/squads` `{squadId}`,
  `DELETE /api/inbounds/:id/squads/:squadId`.
- Состав группы меняется через `PATCH /api/squads/:id/members` или карточку пользователя —
  клиенты всех привязанных подключений обновляются автоматически.
- Удаление группы снимает все привязки и клиентов, пришедших от неё.
- Обратная миграция: `backend/prisma/inbound-squad-down.sql`.
