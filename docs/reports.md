# Отчёты

Раздел `/reports` доступен только администратору (`@Roles(ADMIN)` в
`backend/src/modules/reports/reports.controller.ts`). Есть три вкладки.

## Динамика трафика (по умолчанию)

`GET /api/reports/traffic/timeseries?days=30` (или `?from=YYYY-MM-DD&to=YYYY-MM-DD`):

- суточные корзины `bytesUp` / `bytesDown` / `total` из `UserTraffic`;
- сравнение с предыдущим периодом такой же длины (`summary.changePct`);
- топ-5 пользователей по трафику за период;
- период ограничен 366 днями (`MAX_DAYS`), невалидные даты и `to < from` отклоняются.

В UI: чипы 7/30/90 дней или произвольный диапазон,график с накоплением с накоплением (загрузка/скачивание),
компактные карточки итогов и изменение к прошлому периоду, список топ-пользователей.
Экспорт: `GET /api/reports/traffic/timeseries.csv` — **с теми же фильтрами**, что и экран.

Для ускорения диапазонных запросов добавлен индекс `UserTraffic(createdAt)`.

## По организациям и протоколам

- `GET /api/reports/organizations?from&to` — пользователи, активные пользователи, ноды,
  онлайн-ноды и суммарный трафик по организациям (включая «No organization»).
- `GET /api/reports/protocols` — группировка инбаундов по протоколу.
- CSV: `/api/reports/organizations.csv`, `/api/reports/protocols.csv`.

## Ограничения MVP

- Отчёты ADMIN-only; для OPERATOR изоляция по организации пока не реализована.
- Финансы, per-node/per-outbound срезы и алерты по биллингу — в плане, не в этом MVP.
- Даты в табе «По организациям» влияют только на сумму трафика, не на счётчики
  пользователей/нод — это известное поведение текущего `dateWhere`.
